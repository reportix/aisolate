# AIsolate controller

## Regenerating the goldens

`RendererTest` pins what the controller renders as golden YAML:
`apps/controller/src/test/resources/expected/release.yaml` (the objects of every fixture airlock) and
`apps/controller/src/test/resources/expected/discovery.yaml` (the discovery objects). A diff against a golden is a
deliberate change or a bug, so a golden is regenerated by hand and reviewed, never blindly. Run from the repository
root, which every path below is relative to; no Docker is needed.

1. Get the new render into the golden. Either copy the render that a failing run left in
   `apps/controller/build/actual-release.yaml` over `apps/controller/src/test/resources/expected/release.yaml` (and
   `apps/controller/build/actual-discovery.yaml` over `apps/controller/src/test/resources/expected/discovery.yaml`
   for the discovery golden), or delete the golden.
2. Run `./gradlew :apps:controller:test --tests '*RendererTest'`. After a copy it passes; with the golden deleted
   the test writes it from the current render and fails once, telling you to review it.
3. Review `git diff` of the golden. Every changed line must be a change you meant to make.
4. Run the test again; it passes against the regenerated golden.

The tests beside the golden that assert the policy on their own (pods restricted and carrying their revision,
limits and the tmp cap, discovery leaking no e-mail or secret, discovery pods carrying no airlock's code, data or
model) do not read the golden: if one fails after a regeneration, the regeneration blessed a regression.
